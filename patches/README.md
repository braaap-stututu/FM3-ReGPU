# XenonRecomp patches

Applied in this order to `thirdparty/XenonRecomp` at `ddd128bcca99fe8bfbb99bea583c972351fa6ace`
by `tools/setup.ps1` (which checks the whole stack against the working tree, so it is safe to re-run).

| # | Patch | From | What |
|---|---|---|---|
| 1 | `xenonrecomp-fm2.patch` | FM2-ReGPU / FM4-ReGPU | PowerPC divides never trap (zero divisor / overflow give a value); MSR[EE] toggles become `PPC_MSR_CHANGED` (the runtime's interrupt lock) |
| 2 | `xenonrecomp-modules.patch` | FM4-ReGPU | Optional function-name prefix per image (several images in one program); warns when unnamed imports become no-op thunks |
| 3 | `xenonrecomp-fm4.patch` | FM4-ReGPU | XenonAnalyse jump-table back-trace through registers (tables the fixed patterns miss), bound from masks / `cmplwi`; fallthrough count; XEX loader sizes the image by the security info too |
| 4 | `xenonrecomp-fm4-instructions.patch` | FM4-ReGPU | Missing/incorrect VMX128 and CR-bit instructions (e.g. `vsldoi128` decoded before PPC405 MAC forms) |
| 5 | `xenonrecomp-switch-u32.patch` | FM4-ReGPU | `switch` on the 32-bit table index; `vcmpbfp(128)` implemented instead of a trap |

Source: [Aiden-Piercee/Fuzzy-Rittersport-4-ReGPU](https://github.com/Aiden-Piercee/Fuzzy-Rittersport-4-ReGPU) commit `69bdae44d22a9e0f52733ff55b9f1d0dd5e55b2b` (`patches/`), MIT

All five are generic recompiler fixes, not FM2/FM4 addresses. FM3 is a single image (only
`default.xex` on Disc 1), so patch 2's prefix stays unused for now.

## ReGPU patches (ours)

Applied to `thirdparty/ReGPU` at `57143cb79e8dd4de7b776c70867313cd0b1862f2` by `tools/setup.ps1`. Game-neutral
Xenos behaviour, each behind a `REGPU_*` switch, as ReGPU's own rules ask; candidates to send upstream.

| Patch | What | Switch |
|---|---|---|
| `regpu-fixed16-fetch.patch` | A resolved 16-bit fixed image (copy destination `k_16`, `k_16_16`, `k_16_16_16_16`) read with a **different number format than it was copied in**: back to the 16 bits the console stores (fraction copies hold fraction × 65535, or × 32767 signed; integer copies the integer), then read as the fetch asks (unsigned fraction = bits / 65535, signed fraction = value / 32767, integer = bits). The same format on both sides is unchanged; the border colour is never converted. ReGPU returned the stored values as they were. In FM3 this affects the variance shadow map (resolved as signed integers with exp bias +10, read by its blur as unsigned fractions). History: the first version also converted same-format reads and the border, which darkened the sunlit road and drew a square around the car; corrected (session 8c). It did **not** fix the road streaks (that is the strip write-back in `src/gpu_host.cpp`). | `REGPU_NO_FIXED16_FETCH=1` (start-up) |
| `regpu-zpd-tile-spans.patch` | Occlusion queries under predicated tiling: D3D replays each tile's commands, so a query's ZPD events come as a count-on/count-off pair per tile, and only the last carries the end markers. A second start while counting now pauses the query and the next one resumes it (a new D3D query part); the end sums the parts. ReGPU had counted one span from the first start to the end, including every draw of the next tile's replay. FM3's sun query went from 6,472,508 samples to 5,780: the glare no longer whites out, and the coverage re-draws of the second tile are gone. Also: `REGPU_TRACE_ZPD` logs `RB_SAMPLE_COUNT_CTL` and allows 12 more lines each time it is switched on. | `REGPU_NO_ZPD_SPANS=1` (live) |
| `regpu-resolve-into-image.patch` | A resolve with `rect.top > 0` whose destination address **already holds a resolved image of the same width covering the rectangle's rows** is placed into that image at its own rows. ReGPU treated every full-width resolve with a row offset as a predicated-tiling tile, whose destination is the tile's own row, and subtracted the offset. A real tile names an address where no image starts (FM3's scene tile 2: `18216000`, 512 rows in), so tiles are unchanged. FM3 rebuilds its 512×512 road detail image half at a time, rows 256–511 to the image's own base; as a "tile" that went to a phantom 512×768 image 256 rows earlier, the road image kept a stale blurred lower half, and the asphalt showed smooth bands once the chase camera turned (that's when the half-rebuilds start). | `REGPU_NO_RESOLVE_INTO_IMAGE=1` (live) |
| `regpu-timer-overlay.patch` | Test aid, not Xenos behaviour: a panel in the top-left corner of the picture with the log clock (`LogSeconds()`, the `[time]` at the start of each log line) to a tenth of a second, white on black. The presenter copies it onto the back buffer after the game's frame (like the shader-compile panel, which moves below it), so it is in window screenshots but never in the guest's images. Also shown while the shader-compile hold repeats the last frame. Adds `double LogSeconds()` to `log.h`; a port with its own log must provide it. Off unless set; FM3's `src/gpu_host.cpp` sets it (`FM3_NO_TIMER=1` hides it). | `REGPU_TIMER=1` (live) |
| `regpu-cube-2101010.patch` | **k_2_10_10_10 textures** (Xenos format 7: X in bits 0–9, Y 10–19, Z 20–29, W 30–31) are decoded (8 bits kept per channel; the fetch's exponent adjust is applied in the shader as for any format). They were unsupported and decoded to nothing: FM3's showroom/garage reflection cube is this format (256×256, mipped, read from memory), so it was black: chrome black, paint without reflections. Also, cube maps read from memory: each face's level 0 is now staged at its own place in the upload ring and copied from there; before, it was written at `offset + faceBytes·i` but copied from the running offset, so one-level cubes showed face 0 on every face and mipped cubes got other levels' bytes in level 0. | `REGPU_NO_2_10_10_10=1` (live, textures decoded after), `REGPU_NO_CUBE_FACE_STAGING=1` (live, part of the cube's hash) |
| `regpu-resolve-into-enclosing.patch` | A colour resolve whose destination lies **inside an image resolved earlier** (same pitch, format and bytes per pixel; a whole number of 32×32 tiles past its base, i.e. texel (x, y) of the tiled image; the declared height exactly the rows left below y) is also drawn into that image at (x, y), as the copy writes it on the console. The outermost such image wins (the parts' own images match too). The pass's host scale and the image's may differ, so the blit shaders gained a source step and origin (two more root constants; defaults reproduce the old reads). FM3 builds a car's 2048×2048 texture (body, parts, vinyls) this way: four 2048×512 strips and, per vinyl edit, one rectangle per changed region; each became an image of its own, and the car read the one at the base: vinyls invisible. Each copy is still also resolved as its own image. | `REGPU_NO_RESOLVE_INTO_ENCLOSING=1` (live) |
| `regpu-enclosing-writeback.patch` | A resolve drawn into an enclosing image (previous patch) whose image is **written back to memory** (by the port's `resolveWriteback` hook, Now or Deferred) also writes its rectangle of that image back, Deferred (in memory before the next fence, no stall). On the console the copy lands in memory inside the image anyway; ReGPU wrote only the base resolve, so a title that reads the finished image on the CPU found the base without the parts. FM3 builds each car's livery (2048×2048 and 1024×1024) from strips and vinyl regions and compresses it to DXT on the CPU: written back without the parts, the car had no vinyls or badges in races (issue B2). | `REGPU_NO_ENCLOSING_WRITEBACK=1` (live) |
| `regpu-enclosing-big-pass.patch` | Two gaps in `ResolveIntoEnclosing` for passes drawn in tiles: (1) a **big pass's image is kept at the pass width** (the resolve clamps it to `BigPassSize()`, pitch × 64/65 of the surface: a 1400-wide 4× surface copied with pitch 1408 makes a 1378-wide image), so its later tiles, which name the copy pitch, never matched it; the image now matches either width. (2) A **last tile whose rectangle is rounded up to 8 rows past the image** (88 rows copied, 86 declared) was refused; it is clipped to the image (the draw already was). FM3 renders each big vinyl region's side view as a 4×MSAA pass in 224-row tiles: only the first tile reached the image, so the vinyls on the car's sides and hood stopped at a straight line (issue B). | `REGPU_NO_ENCLOSING_PASS_WIDTH=1`, `REGPU_NO_ENCLOSING_ROW_CLIP=1` (live; take effect at the next build of the pass, e.g. a car load) |
| `regpu-writeback-safety.patch` | Three fixes after a car vanished from the garage (FM3 issue H, session 11). (1) The big-pass width match of `regpu-enclosing-big-pass` applies **only when the current pass is a big pass**: for an ordinary pass the clamp is the 1280-wide output, and a 704×264 copy with pitch 2048 (a car's bumper region) matched any 1280-wide image below it (a menu poster showed the bumper's vinyl). (2) A deferred write-back **skips memory the title has written since the resolve** (dense hash of the bytes it covers, taken when queued and again before writing; our own write-backs to the same image don't count), as the FM4 port's ReGPU does: the console writes a resolve when the GPU runs it, ours lands before the next fence or a frame or two later. Logged as `writeback: … the memory changed since the resolve`. (3) The **written-back mark is cleared** when a resolve at the same address isn't written back: it used to stay with the address after the title reused it, so a later resolve drawn into that image (e.g. through the bug in (1)) was written into memory that held other data. Together (1) and (3) are the likely cause of the vanishing cars: with them the car survived the same sequence that lost it, without (2) firing. | `REGPU_NO_ENCLOSING_PASS_WIDTH=1` (as part of the big-pass match), `REGPU_NO_WRITEBACK_REUSE_CHECK=1`, `REGPU_KEEP_WRITEBACK_MARK=1` (live) |
| `regpu-guest-lod-short-mips.patch` | Textures with a short mip chain (smallest level still 64 texels or more) are sampled at the mip level the console would pick: LOD bias + log2 of the draw scale when rendering above 1x. Such chains can hold separate images per level (FM3 keeps a car's 512x256 picture at level 0 and its 256x128 side-view thumbnail at level 1), and the host's finer pick blended both (FM3 My Cars thumbnails at 1440p, session 12). Full chains keep the sharper host pick. `REGPU_NO_GUEST_LOD_SHORT_MIPS=1` (live) turns it off. |
| `regpu-early-fence-writebacks.patch` | With early fences (`REGPU_EARLY_FENCES`), a fence behind a deferred resolve write-back still waits for the host GPU and the write-back, as `RendererFenceSubmit` already asks: the command processor's `WriteBack` zeroed every fence, so a title that reads a resolved image on its CPU once it sees the fence read it unwritten (FM3's car liveries: noise or blank). All other fences stay early. `REGPU_EARLY_FENCES_SKIP_WRITEBACKS=1` restores the old behaviour (A/B). Session 13. |
| `regpu-worker-queries.patch` | Occlusion queries with draw workers (`REGPU_DRAW_WORKERS`): ReGPU answered every query a fixed 1000 then (a D3D12 query only counts the draws of its own list, and the workers record theirs into their own), so FM3 showed no sun flare/glare. Now a ZPD start flushes the open logged segment and, while the query counts (`RendererOcclusionCounting`: between a start and its tile-span pause or end, `regpu-zpd-tile-spans`), its draws go straight to the command processor's list (`seg::g_query`); between the spans and outside queries the workers go on. Worker draws never take a coverage draw of the command processor's query. Simpler than PGR4's logged queries (3cbd0f4), which would split our tile spans across pieces. `REGPU_NO_WORKER_QUERIES=1` (live): the fixed answer again. Session 14. |
| `regpu-zpd-scale.patch` | `REGPU_ZPD_SCALE=<f>`: multiplies every occlusion query answer (read from the environment every 64 answers, so `Fm3 "env REGPU_ZPD_SCALE x"` works live). FM3 sizes its sun glare from the raw sample count; at 1x the glare was far bigger than console footage, and `src/gpu_host.cpp` sets 0.6 (matched by eye). Default 1 (unchanged). Session 14. |
| `regpu-draw-thread-pieces.patch` | The draw thread (`REGPU_DRAW_THREAD`) together with the draw workers: the command processor only parses and queues (registers, shaders, draws, fences, swaps, occlusion query records); the draw thread runs the parallel segments (`seg::`, which ran on the command processor and was off with the draw thread) and hands big ones to the workers. Occlusion queries with the draw thread (before: a fixed 1000, no sun flare): the command processor answers from earlier frames (`RendererOcclusionAnswer`, place per address counted there) and the draw thread records the query in stream order (`work::kQuery`: `RendererOcclusionBegin` for every start, keeping our tile spans; `RendererOcclusionEndOn`); the results map is locked. Snapshots copy the translating thread's register file (`gpureg::File()`). FM3 cars grid, paused: 720p 1x 175 -> 202 fps, 1440p 4x MSAA 175 -> 181 (GPU-bound there). `REGPU_DRAW_THREAD_SERIAL=1` (at start): the draw thread translates alone. Session 14. Session 15: the command processor no longer clears `seg::g_query` at a query's end with the draw thread (it ran ahead and sent the query's draws to worker lists: no sun flare with the workers on the draw thread). |
| `regpu-capture-vertex-floats.patch` | Debugging only: in a traced frame (capture), vertex buffers of up to 64 dwords are also logged in full as big-endian floats (`vf<N> floats: ...`), so a screen-space quad's corners and texture coordinates can be read from the log; the buffer is usually reused by the time it could be peeked. No effect outside captures. | — |

| `regpu-livery-enclosing-recent.patch` | (1) `ResolveIntoEnclosing` collects every matching image and takes the lowest base among those used in the last 120 frames: FM3 builds each car's livery in a new image a few KB above the previous load's, which still matched at a lower base, so pieces went into the old image (the write-back safety check then dropped them: livery broken except one section, fixed on the next load). Logs `resolve: X fits N images: ...` when more than one matches. `REGPU_ENCLOSING_LOWEST=1`: the lowest of all (old). (2) The deferred write-back safety check keeps a snapshot of the span at queue time and compares texel by texel: written when nothing inside its own rectangle changed (the span covers whole 32-row blocks across the width), and the log says where the change was. `REGPU_WRITEBACK_REUSE_SPAN=1`: any change skips it (old). Session 16. |
| `regpu-msaa-color-clear-scale.patch` | A texture-less rectangle through an MSAA view of a small surface whose textured draws are 1x is scaled to the 1x layout, like the existing depth-only shadow-map clear: FM3 clears the 256x256 image of the track's shade around the player's car with a 120x128 rectangle through a 4x view (pitch 160) plus a 16-pixel strip; unscaled, three quarters kept the shade drawn for an AI car in the pass before (other cars' shade flickered on the player's car, OPEN-ISSUES E). Only when pitch x samples across < 1000 (the 1280-wide scene is also cleared through a 4x view: scaled, it whitened a quarter of the screen). `REGPU_NO_MSAA_COLOR_SCALE=1`: off. Session 16. |
| `regpu-debug-shot-dump.patch` | After a capture, `g_hotkeyFrame` kept its value, so every later debug-server shot also wrote every resolved image to `out/res` (~30 s per shot with thousands): only the captured frame dumps resolves now. Session 16. |
| `regpu-turbo-hyper.patch` | Speed pieces behind the launcher's speed presets (session 19, modelled on a ReGPU study of FM2's "Turbo/Hyper" modes whose code isn't public; our own implementations). Turbo, same picture: `REGPU_LEAN_FETCH=2` (a plain 2D texture, flagged on the CPU as tinfo.x bit 7, is one sample; the instruction's filter is honoured), `REGPU_LEAN_VFETCH` (vertex fetches load only their format's dwords), `REGPU_INDEX_HASH_ONCE` (index lists fully hashed once a frame, a sampled probe at later draws), `REGPU_DRAW_CULL=<px>` (live; depth-writing draws that covered fewer pixels the last time are predicated off, retested every other frame, so above 1 px small things flicker: the presets use 1; per-draw occlusion queries, one batched resolve and a compute pass at frame end; new `RecordedList` ops for predication and root SRV/UAV), `REGPU_COPIES_1010102` (2_10_10_10 copies kept as R10G10B10A2, not half floats; write-backs decode it), `REGPU_A2M_AS_TEST` (alpha to mask as a 0.5 test at 1x MSAA), `REGPU_PLAIN_MUL_PS` (pixel shaders multiply as IEEE). Hyper, visible: `REGPU_HELPER_SCALE` (passes narrower than the screen at a share of the scale; not big or tall passes), `REGPU_FREEZE_HELPERS=<n>` (steady narrow 8888/2_10_10_10 colour passes with depth-tested draws drawn every n-th frame). |
| `regpu-vertex-arena.patch` | The vertex arena, from the FM2 port (session 19): `REGPU_VERTEX_ARENA=1` (start-time) keeps large vertex buffers in a 512 MB arena in video memory, bound as t1, copied again only when the port's write watch (new `Host::watchArm`, `watchClean`, `watchSeq`; FM3: `src/memory.cpp`) saw a write to one of their pages (or hashed once a frame without it); read in place, the GPU fetched them over PCIe in every draw. Arena frames draw triangle lists and strips indexed from the index arena (no in-place indices). With the arena the GPU's heap is opened over a view of guest memory of its own (`HeapViewAddress`): over the guest's 0xA0000000 view Windows refuses read-only protection (error 87) and the arena turned itself off, as FM2's does on such PCs. `REGPU_NO_VERTEX_ARENA` (live, next frame), `REGPU_VERTEX_HASH` (hash instead of watching), `REGPU_VERTEX_VERIFY` (log writes the watch missed), `REGPU_GUEST_VIEW_HEAP` (the old heap view). |
| `regpu-split-alpha-test.patch` | Session 20: ReGPU applies the alpha test at run time (`switch (pinfo.x)` ending in `discard`), so every translated pixel shader could discard and, with depth writes, the GPU may drop early depth rejection. `REGPU_SPLIT_ALPHA_TEST=1` (live): draws with the alpha test (a function other than always) and alpha-to-mask off use a variant of their pixel shader without that block (`NoKillShader`, built from the HLSL like the motion variant, pipeline flag `0x400`; such pipelines are stored in the pipeline manifest and rebuilt at boot from the base shader's variant, `ManifestPixelShader`). Guest kill instructions stay. FM3 turns it on by default (`FM3_ALPHA_KILL_ALWAYS=1` off): CrownJewel race grid 203 -> 213.6 fps, picture byte-identical. |
| `regpu-gpu-stats.patch` | Session 23 (PERF-PLAN L4, overdraw): `REGPU_GPU_PASSES=2` (read at start) also wraps every draw in a D3D12 pipeline statistics query (begun and ended in the draw's own list) and logs, every 2 s with the pass times, pixel shader invocations per frame (and per output pixel), then the top 20 passes and pixel shaders by invocations (with vertex invocations, primitives and draws). Draw workers' draws are not counted: measure with `REGPU_DRAW_WORKERS=0`. Measurement only; off unless asked for. |
| `regpu-seed-variants.patch` | Session 24 (first-boot shader compile): (1) `BuildSeedPipelines` built flag-0x400 seed pipelines with the base pixel shader instead of its alpha-test-free variant (`ManifestPixelShader`, as the warm-up and draws do): same picture, without the variant's speed; now the variants are queued together and used. (2) The static-shader wait stops once at most 3 are left and they have compiled for 5 s (FM3: one never-drawn vertex shader took 37-44 s of a 55 s first boot); they finish in the background, and seed pipelines whose shaders are still compiling move to the run-time list. `REGPU_STATIC_WAIT_ALL=1` waits for all. |
| `regpu-fetch-variants.patch` | Session 24 (PERF-PLAN L30): `REGPU_FETCH_VARIANTS=1` (live; the FM3 port sets it with lean fetch): each draw works out which of the pixel shader's texture slots are "plain" this draw (2D, whole image, no 16-bit fixed conversion, exponent, border, single-axis clamp, gamma, mirror or non-identity swizzle: lean fetch 2's bit-7 test) and, once compiled, draws with a variant whose lean fetches of those slots (`TFetch2D`/`TFetch2DV2`) call `TFetchPlain` (one sample with the constant's sampler). Built from the HLSL like the alpha-test-free variant (on top of it when both apply), at most 16 per shader; the pipeline key gains `fetchMask` (a 9th manifest field when set; the warm-up, seed and run-time list rebuild it); a variant's pipeline never makes a draw wait. FM3 car paint: 117 KB -> 20 KB of RDNA3 code, GPU frame -2.5%, byte-identical. Also `REGPU_DUMP_ROOTSIG=<file>`: the root signature for RGA (`tools/rga_shaders.ps1`). |
| `regpu-draw-thread-cuts.patch` | Session 24 (CPU side): two locks off the draw thread's per-draw path, found by sampling it (`FM3_SAMPLE_THREAD=name:gpu draw worker`): `IsPsEditAlias` (asked several times a draw) takes no mutex until a live shader edit exists; `FetchShader` memoises its lookups per thread. With our host's `FM3_WRITEBACK` read throttled: CPU-bound grid (720p 1x) 214.5 -> 220.5 fps over two boots each. |
| `regpu-shader-repeat-skip.patch` | Session 24 (CPU side): with the draw thread, the command processor compares each shader load with the last one of its type it sent and drops exact repeats (55% of FM3's ~2,200 loads a frame), saving the draw thread the copy and the microcode compare. Memo cleared whenever loads take the other path. `REGPU_NO_SHADER_REPEAT_SKIP=1` sends every load (live). CPU-bound grid: +2.4%, 5/5 interleaved rounds, 0 pixels differ. |
